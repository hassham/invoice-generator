# BEVORLY — Brand Identity & Design System

Version: 1.0

## 1. Agent role

Act as a senior brand designer, creative director, UX architect and frontend design engineer responsible for the visual identity of BEVORLY.

All public websites, application interfaces, onboarding experiences, components, illustrations, marketing materials and system communications must adhere to these branding guidelines.

The supplied visual reference establishes the creative direction. Adapt its aesthetic to a professional financial SaaS application rather than reproducing its content literally.

## 2. Product overview

Brand name: BEVORLY

Preferred visual wordmark: bevorly.

Product category: Invoice and client management SaaS.

Target audience: Freelancers, independent professionals, consultants, entrepreneurs and small businesses.

BEVORLY simplifies business administration by helping users create invoices, manage clients, track payments and understand their business finances.

Primary tagline: "Less paperwork. More business."

Secondary tagline: "Business, minus the boring."

Brand promise: Make business administration effortless, approachable and beautifully organised.

## 3. Creative direction

The BEVORLY design identity is called Playful Professionalism.

It combines:

- Soft neo-brutalism.
- Modern retro editorial design.
- Contemporary independent software aesthetics.
- Flat pastel colours.
- Oversized, expressive typography.
- Hand-drawn geometric illustrations.
- Strong black outlines.
- Warm, paper-inspired backgrounds.
- Playful minimalism.
- Structured and professional application interfaces.

BEVORLY must feel approachable, modern, trustworthy, memorable and distinctive.

The product should not resemble traditional accounting software, generic enterprise dashboards or standard AI-generated SaaS templates.

The interface must balance personality with financial clarity.

## 4. Brand personality

BEVORLY is:

- Confident without being arrogant.
- Playful without being childish.
- Professional without being corporate.
- Friendly without being overly familiar.
- Minimal without being visually boring.
- Organised without being restrictive.
- Modern without relying on temporary design trends.

## 6. Typography

Primary display font: Space Grotesk.

Primary body and application font: DM Sans.

Utility and financial data font: Space Mono.

Display typography should be bold, tightly spaced and visually confident.

Marketing typography:
- Hero headings: 64–96px, weight 700.
- Section headings: 40–56px, weight 700.
- Supporting copy: 18–22px.
- Use responsive CSS clamp() values.

Application typography:
- Page headings: 28–36px, weight 700.
- Section headings: 20–24px, weight 600–700.
- Card headings: 18–20px, weight 600.
- Body: 14–16px.
- Labels: 12–14px, weight 500–600.
- Tables: 14px.
- Financial metrics: 24–36px.
- Invoice references: 12–14px.

Display headings may use negative letter spacing between -0.03em and -0.05em.

Body text must prioritise readability.

Use tabular numerals for financial amounts and right-align comparable amounts within tables.

Support different currencies and regional number formats.

## 7. Brand logo

The preferred wordmark is "bevorly." using bold lowercase typography.

The logo should be simple, distinctive and legible at small sizes.

Develop a recognisable brand symbol using geometric forms, bold black outlines and electric lime.

Possible directions include an abstract letter B, an invoice-inspired symbol or a geometric mark representing organisation and completion.

The final brand mark must remain recognisable independently of an invoice illustration.

Required logo variations:

- Primary horizontal wordmark.
- Standalone brand symbol.
- Monogram.
- Favicon.
- Monochrome version.
- Light-background version.
- Dark-background version.

Do not use gradients, glossy effects, bevels or complex illustrations inside the logo.

## 8. Spacing and geometry

Use a consistent spacing system based on multiples of 4px and 8px.

Recommended spacing tokens:
4, 8, 12, 16, 24, 32, 40, 48, 64, 80 and 96px.

Corner radius system:
- Compact elements: 6–8px.
- Inputs: 8–12px.
- Application cards: 12–20px.
- Feature cards: 24–32px.
- Marketing cards: 32–40px.
- Buttons and status indicators: pill-shaped where appropriate.

Border system:
- Standard application borders: 1px.
- Emphasised application controls: 1.5px.
- Primary marketing controls: 2px.
- Illustration strokes: approximately 2–4px depending on scale.

Avoid placing thick borders around every element. Strong borders should establish emphasis and hierarchy.

## 9. Marketing website

The public-facing marketing website should be highly expressive.

Use:
- Oversized editorial headlines.
- Warm neutral backgrounds.
- Staggered or asymmetrical card compositions.
- Large flat pastel feature cards.
- Custom hand-drawn illustrations.
- Hand-drawn underlines and accent marks.
- Electric lime calls to action.
- Slightly rotated decorative cards where appropriate.
- Generous whitespace.
- Short, memorable copy.
- Realistic application previews.
- Distinctive but restrained interactions.

Cards may rotate by approximately 1–2 degrees in decorative marketing compositions.

The marketing website should create an immediate visual impression that differentiates BEVORLY from conventional invoicing platforms.

Do not sacrifice usability or accessibility for creative expression.

## 10. SaaS application

The authenticated application must use a more disciplined interpretation of the same brand identity.

Use:
- A structured sidebar or navigation system.
- A warm neutral application shell.
- Clean paper-like content surfaces.
- Compact, expressive page headings.
- Carefully positioned pastel metric cards.
- Consistent action placement.
- Clear financial summaries.
- Structured tables.
- Consistent forms.
- Contextual illustrations in empty and success states.

Do not use rotated components within application workflows.

Do not use excessive illustrations or decorative elements around financial data.

Prioritise rapid scanning, data accuracy, predictable interaction patterns and accessibility.

Maintain consistent page anatomy across invoices, clients, payments, expenses, reports and settings.

The application must feel like the same brand as the marketing website without looking like a marketing website.

## 11. Buttons

Primary buttons:
- Electric lime background.
- Ink black text.
- Dark outline.
- Medium or semibold typography.
- Pill shape or appropriate application variant.

Secondary buttons:
- Warm neutral or paper background.
- Dark text.
- Visible outline.

Tertiary buttons:
- Minimal text or icon treatment.
- Clear hover and focus states.

Destructive buttons:
- Semantic red styling.
- Clear action labels.
- Appropriate confirmation for irreversible actions.

Primary actions must be visually distinct.

Do not place multiple competing primary buttons within the same workflow.

## 12. Cards

Marketing cards:
- Large corner radii.
- Flat pastel backgrounds.
- Large illustrations.
- Bold titles.
- Generous internal spacing.
- Occasional decorative asymmetry.

Application cards:
- Controlled corner radii.
- Paper or semantic pastel surfaces.
- Clear metric labels.
- Readable numerical values.
- Consistent alignment.
- Minimal decoration.

Use cards only when they improve grouping, hierarchy or interaction.

Do not wrap every piece of content in a card.

## 13. Forms

Forms must be clear, practical and consistent.

Use:
- Visible labels above inputs.
- Comfortable field spacing.
- Clear input outlines.
- Accessible focus indicators.
- Helpful validation messages.
- Contextual assistance.
- Logical grouping of related fields.
- Responsive layouts.

Do not rely on placeholders as the only labels.

Financial forms must clearly identify currency, tax, discounts, totals and payment terms.

Important values should be visually distinguished from ordinary descriptive information.

Invoice creation should be efficient and optimised for repeat usage.

## 14. Tables and financial data

Financial tables must remain clean and highly readable.

Use:
- Left-aligned text.
- Right-aligned monetary values.
- Consistent column widths.
- Tabular numerals.
- Clear sorting and filtering.
- Compact row actions.
- Visible status labels.
- Accessible hover and selection states.
- Logical pagination where required.

Avoid thick borders between every table cell.

Never use decorative typography for monetary values where it reduces readability.

Financial summaries must make clear which values are invoiced, received, outstanding or overdue.

## 15. Illustration and iconography

Create a consistent library of custom doodle-style illustrations.

Illustration characteristics:
- Thick black outlines.
- Rounded strokes.
- Simple geometric objects.
- Flat white and pastel fills.
- Occasional electric lime highlights.
- Slightly imperfect hand-drawn character.
- Minimal detail.
- Friendly, expressive visual language.

Illustration themes include:
- Invoices.
- Clients.
- Payments.
- Receipts.
- Expenses.
- Reports.
- Reminders.
- Business organisation.
- Completion and success.

Prefer reusable SVG illustrations.

Use a consistent functional icon library, such as Lucide, for navigation, controls and operational interfaces.

Do not mix unrelated illustration styles.

Do not use stock imagery, glossy 3D assets or generic AI-generated illustrations as the primary visual identity.

## 16. Motion and interactions

Use motion to provide feedback and improve the experience.

Permitted:
- Subtle button press effects.
- Gentle hover translations.
- Animated directional arrows.
- Small success animations.
- Restrained marketing card rotations.
- Smooth disclosure and modal transitions.
- Brief contextual illustration animations.

Application interactions should generally complete within 120–220ms.

Marketing interactions may extend to 200–350ms where appropriate.

Avoid continuous decorative motion, distracting parallax and unnecessary animation during financial workflows.

Respect prefers-reduced-motion.

## 17. Charts and visualisation

Charts should use the approved brand palette where practical.

Use pastel colours with adequate contrast, clear labels and restrained outlines.

Chart appearance:
- Simple geometric shapes.
- Minimal grid lines.
- Readable axes.
- Clear units.
- Accessible legends.
- Consistent numerical formatting.

Do not use 3D charts, excessive gradients or decorative visualisations that distort the interpretation of financial information.

Never sacrifice accuracy for aesthetics.

## 18. Brand voice

The brand voice is approachable, confident, concise and intelligent.

Use human language rather than enterprise jargon.

Example copy:
- Less paperwork. More business.
- Your business at a glance.
- Let's get you paid.
- Invoice sent. Nice.
- Every business starts somewhere.
- A little nudge goes a long way.
- Your business. Beautifully organised.

Use playful copy in:
- Marketing headlines.
- Onboarding.
- Empty states.
- Non-critical success messages.
- Feature announcements.

Use precise and professional copy in:
- Payment confirmations.
- Financial warnings.
- Tax information.
- Subscription terms.
- Security messages.
- Error recovery.
- Destructive confirmations.

Never use humour when it could confuse the user or minimise a financial problem.

## 19. Customer-facing invoice templates

Support multiple professional invoice templates.

Templates must support:
- Customer logos.
- Customer brand colours.
- Business details.
- Client details.
- Unique invoice references.
- Issue and due dates.
- Itemised charges.
- Discounts.
- Applicable taxes.
- Currency.
- Totals.
- Payment instructions.
- Notes and terms.

Invoice documents must prioritise the customer's identity rather than BEVORLY's identity.

A discreet "Invoiced with Bevorly" footer may be used according to product configuration.

Ensure invoice templates support accurate PDF rendering, printing and relevant jurisdiction-specific requirements.

Do not make invoices unnecessarily playful or decorative.

## 20. Accessibility

Maintain WCAG 2.2 AA as the design target.

Ensure:
- Appropriate text contrast.
- Visible keyboard focus.
- Keyboard-accessible interactions.
- Semantic HTML.
- Accessible form labels.
- Descriptive error messages.
- Accessible tables.
- Responsive interfaces.
- Reduced-motion support.
- Status indicators that do not rely solely on colour.

Decorative illustrations must not interfere with application functionality.

## 21. Design restrictions

Never default to:
- Generic blue and purple SaaS gradients.
- Glassmorphism.
- Excessive drop shadows.
- Generic enterprise dashboard styling.
- Corporate stock photography.
- Unnecessary cards.
- Excessive pill-shaped containers.
- Random illustrations.
- Inconsistent icon libraries.
- Oversized headings inside transactional workflows.
- Decorative financial tables.
- Low-contrast text.
- Unmodified component-library defaults.
- Excessive animations.
- Inconsistent spacing.
- Arbitrary colours.

Avoid making the product look childish, cluttered or untrustworthy.

## 22. Implementation architecture

Implement the brand as a reusable design system rather than hardcoded styles.

Maintain central definitions for:
- Colour tokens.
- Typography tokens.
- Spacing tokens.
- Radius tokens.
- Border tokens.
- Semantic status tokens.
- Motion tokens.
- Responsive breakpoints.
- Component variants.

Create shared components for:
- Buttons.
- Inputs.
- Selects.
- Checkboxes.
- Cards.
- Metric summaries.
- Data tables.
- Status indicators.
- Dialogs.
- Toasts.
- Empty states.
- Success states.
- Navigation.
- Page headers.
- Charts.
- Invoice previews.
- Illustrations.

If the application uses Tailwind CSS, map brand tokens to its theme configuration.

If it uses a component library such as shadcn/ui, customise the underlying tokens and components to match BEVORLY instead of using default styling.

Respect the existing application architecture and technology choices.

## 23. Development agent workflow

Before implementing any visual feature:

1. Read BRAND_GUIDELINES.md.
2. Review the approved visual references.
3. Inspect existing design tokens and shared components.
4. Identify whether the feature belongs to marketing, application or customer-facing documents.
5. Apply the corresponding visual rules.
6. Reuse existing components and tokens.
7. Implement responsive and accessible behaviour.
8. Review the rendered interface.
9. Verify consistency with the brand.
10. Fix visual inconsistencies before completing the task.

Do not introduce new visual patterns, colours or typography without a documented reason.

## 24. Definition of done

A frontend task is complete only when:

- Functional requirements are satisfied.
- The implementation follows BEVORLY's visual identity.
- Existing design tokens are reused.
- Shared components are used where appropriate.
- Desktop and mobile layouts are verified.
- Accessibility requirements are met.
- Financial data is clearly presented.
- Loading, empty, error and success states are handled.
- No generic or uncustomised component styles remain.
- The rendered interface has undergone visual review.

The final product should feel distinctive, approachable, reliable and professionally designed.

BEVORLY is not another boring invoicing application.

It is business administration with personality, clarity and confidence.
